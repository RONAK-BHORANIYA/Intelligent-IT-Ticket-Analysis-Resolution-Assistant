Ticket Assistant Architecture
HCLTech hackathon · Use case 1 · Architecture v1

Intelligent IT Ticket Analysis & Resolution Assistant

The assistant classifies an incoming ticket, finds similar past tickets and recommends a fix. Every fix cites a verified source, and the assistant escalates instead of guessing. The ticket corpus answers “what is this?”, a curated KB answers “how do we fix it?”, and a free LLM combines the two under a citation validator. No paid API key is needed.

Request pipeline · POST /analyze · target < 4 s

Six stages, each one testable on its own

1 · redact.py

Redactor

Masks emails, IPs, employee IDs and secrets before indexing, the LLM call, storage and export.

~2 ms
2 · baseline.py

Baseline classifier

TF-IDF + LogReg. Used as the fallback, the agreement signal and the evaluation comparison.

~10 ms
3 · retriever.py

Hybrid retriever

ChromaDB semantic search + BM25, combined 0.6 / 0.3 / 0.1 with metadata. Filters run as Chroma where clauses.

~100 ms
4 · llm_provider.py

Free LLM chain

Groq → Gemini over free API keys, in JSON mode. Pydantic validation plus one repair retry. Can only cite the IDs it was given.

1–2 s (Groq)
5 · validator.py

Evidence validator

Each cited ID must have been retrieved, and each excerpt must be a substring of its source. Fails → retry once, then fall back.

~5 ms
6 · confidence.py

Confidence gate

Three independent signals → OK / NEEDS_REVIEW / ESCALATE, with the reasons stated.

~1 ms

FR-05 · Confidence & fallback

The LLM's own confidence is never used alone

score = 0.35 · llm_conf + 0.40 · retrieval + 0.25 · agreement retrieval = 0.5 · top KB score + 0.5 · mean(top-3 ticket scores) agreement = LLM vs baseline label × neighbour label consensus
OKscore ≥ 0.70, at least 1 valid citation, priority not P1.
NEEDS_REVIEWscore 0.45–0.70, any P1 ticket, any claim removed by the validator, or degraded LLM mode.
ESCALATEscore < 0.45, no valid evidence, top KB score < 0.30 (knowledge gap), or the LLM reports insufficient evidence. Returns the suggested assignment group and clarifying questions.
LayerTriggerBehaviour
L1 NormalValid JSON + citationsFull pipeline
L2 RetryBad JSON or zero valid citationsOne repair retry, with the validator's errors added to the prompt
L2b FailoverGroq 429 / timeoutSame prompt sent to Gemini
L3 DegradedEvery provider failedBaseline labels + top KB steps verbatim, capped at NEEDS_REVIEW
L4 EmptyNo hits above the minimum scoreESCALATE with clarifying questions

Decisions

Trade-offs we chose

DecisionChosenWhy
Resolution sourceCurated KB, with tickets as supporting evidenceReal datasets usually lack resolution text; the brief scores traceability
Vector storeChromaDB (embedded, persistent) + BM25Built-in metadata filters, persists on disk, no server; NumPy fallback behind the same interface
LLM providerFree API keys: Groq → GeminiNo paid key and nothing to run locally; rate limits handled by failover and the response cache
ClassifierLLM with a closed label set, plus a TF-IDF baselineFallback, agreement signal and a comparison for the evaluation
ConfidenceThree combined signalsLLM self-reported confidence is poorly calibrated
UI ↔ coreStreamlit over FastAPIMeets “interface or API”; the UI can be swapped later
